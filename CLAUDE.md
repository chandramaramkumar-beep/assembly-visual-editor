# Assembly Visual Editor

Interactive web app that teaches x86_64 assembly (Intel/NASM syntax) by animating exactly how the stack and registers change as a student writes and steps through code. Not a compiler, not a VM — a small fixed lookup table of state-transition rules over a defined teaching instruction subset.

Full rationale lives in `../docs/*.md` (one level up from this repo): `01-visualization-and-animation-design.md`, `02-tech-stack-visualization.md`, `03-full-stack-architecture.md`, `04-build-prompt.md`. Read `04-build-prompt.md` first if anything here is ambiguous.

**Read `AGENTS.md` before touching Next.js APIs.** This project is on Next.js 16 (App Router), which has breaking changes vs. older training data — page/layout prop types, routing conventions, and config shape may differ from what you expect. `AGENTS.md` is regenerated by `next dev`/`next build`; don't remove its content, only append.

## Hard constraints

- **Never build a general-purpose instruction executor.** No real memory addressing, no syscalls, no interrupts, no paging. If you're implementing something that could run arbitrary/unbounded programs against real memory semantics, stop — that's out of scope.
- **Computer-independent.** Nothing is ever pulled from a real running process, debugger, or hardware. All state comes from simulating our own rules for our own instruction subset.
- **The deterministic core (`lib/engine/`) must never be wrong.** See `lib/engine/CLAUDE.md` for the rules that keep it that way.
- **Do not implement the intent/chatbox feature** (comparing student-stated intent against the trace). It's deliberately deferred — leave the extension point in `lib/agents/`, don't build it.

## Architecture

Two strictly separated responsibilities — keep this boundary visible in the folder structure, not just in your head:

1. **`lib/engine/`** — deterministic ground-truth core. Pure functions, immutable state snapshots, zero judgment calls.
2. **`lib/agents/`** — AI presentation layer. Consumes the trace the core already computed; decides what to highlight/narrate/compress. Never computes state itself.

## Repo map

```
app/                    # Next.js App Router: routes, pages, API routes for AI agent calls
lib/engine/             # deterministic core — see lib/engine/CLAUDE.md
lib/engine/__tests__/   # Vitest + fast-check property tests for the core
lib/agents/             # AI orchestration — see lib/agents/CLAUDE.md
components/             # UI: code editor panel, stack visualization, register panel, controls
```

## Tech stack

TypeScript end to end (no Rust/WASM, no separate backend language). Next.js App Router. CodeMirror 6 with a custom Lezer grammar for the teaching-subset dialect (not Monaco). Motion for frame layout animation. GSAP for choreographed sequences (loop pulse, thumbnail collapse). XState for playback state (`idle → playing → paused → jumped → thumbnail-parked`). Zustand for general UI state — don't route that through XState. Vercel AI SDK for AI calls, called only from API routes/server actions — never from client-side code. Vitest + fast-check (`@fast-check/vitest`) for testing the core.

## Commands

- `npm run dev` — start dev server (localhost:3000)
- `npm test` — run Vitest once (includes fast-check property tests under `lib/engine/__tests__/`)
- `npm run test:watch` — Vitest watch mode
- `npm run typecheck` — TypeScript check (`tsc --noEmit`)
- `npm run lint` — ESLint
- `npx next typegen` — regenerate Next.js route types if `tsc` complains about missing route/layout types (e.g. `LayoutProps`) after a fresh checkout — these are gitignored and generated by `next dev`/`next build`/`next typegen`, not committed

## Workflow rules

- Any change to `lib/engine/` needs a property-based test alongside it, not just example tests — see `lib/engine/CLAUDE.md`.
- Adding a new instruction to the teaching subset must be done via the discriminated union so the compiler forces exhaustive handling in every switch — the build should fail to compile until the new instruction's rule exists.
- Don't add instructions, UI features, or abstractions beyond the current build phase (see `04-build-prompt.md` "Suggested build phases"). This is a personal/small project, not a team codebase — keep scope tight.
